# 로그인 실습 요구사항

## 화면과 기능

| 항목 | 조건 또는 동작 | 기대 결과 |
| --- | --- | --- |
| 로그인 화면 | `/` 또는 `/login`에 비로그인 상태로 접근 | `/login`에 이메일, 비밀번호, 비밀번호 표시 버튼 및 로그인 버튼이 표시된다. |
| 필수 입력 | 입력 없이 제출 | 각 필드 아래에 ‘이메일을 입력해 주세요.’와 ‘비밀번호를 입력해 주세요.’가 표시된다. 첫 번째 오류 필드로 초점이 이동한다. |
| 이메일 형식 | `invalid-email`처럼 형식이 맞지 않는 이메일로 제출 | 이메일 아래에 ‘올바른 이메일 형식을 입력해 주세요.’가 표시된다. 인증을 시도하지 않는다. |
| 인증 실패 | 이메일 형식은 올바르지만 계정 정보가 일치하지 않는 상태로 제출 | `/login`에 머무르고 ‘이메일 또는 비밀번호가 올바르지 않습니다.’가 표시된다. |
| 비밀번호 표시 | ‘비밀번호 표시’ 버튼을 반복해서 누름 | 처음에는 비밀번호가 가려져 있다. 버튼을 누를 때마다 입력값을 유지하면서 표시 여부가 바뀐다. |
| 인증 성공 | `tester@example.com`과 `Test1234!`로 제출 | `/dashboard`로 이동하고 테스트 계정 이메일과 로그아웃 버튼이 표시된다. |
| 로그아웃 | ‘로그아웃’ 버튼을 누름 | 로그인 상태가 초기화되고 `/login`으로 이동한다. |
| 대시보드 접근 | 비로그인 상태로 `/dashboard`에 접근하거나 로그인 후 새로고침 | `/login`으로 이동한다. 로그인 상태는 브라우저 저장소에 기록하지 않는다. |
| 중복 제출 방지 | 유효한 값을 제출한 뒤 처리 중에 추가 입력, 클릭 또는 Enter 제출을 시도 | 약 650ms 동안 버튼에 ‘로그인 중…’이 표시된다. 버튼은 비활성화되고 입력값은 읽기 전용이 되며 추가 요청은 실행되지 않는다. 실패 후에는 다시 제출할 수 있다. |
| 키보드 조작 | Tab, Shift+Tab, Enter, Space로 조작 | 입력과 버튼 사이를 이동할 수 있다. Enter로 제출하고 Enter 또는 Space로 포커스된 토글과 로그아웃 버튼을 실행할 수 있다. 화면 이동 시 해당 페이지 제목에 초점이 간다. |
| 반응형 배치 | 화면 너비가 44rem 이하로 줄어듦 | 로그인 안내와 폼이 한 열로 배치된다. 넓은 화면에서는 두 열로 배치된다. |

이메일 앞뒤 공백과 대소문자는 계정 일치 여부에 영향을 주지 않습니다. 비밀번호는 입력한 문자열 그대로 비교합니다.

## 안정적인 접근성 이름

| 역할 | 접근성 이름 또는 상태 |
| --- | --- |
| 이메일 입력 | `이메일` label |
| 비밀번호 입력 | `비밀번호` label |
| 표시 전환 버튼 | `비밀번호 표시`, 표시 중에는 `aria-pressed="true"` |
| 로그인 버튼 | `로그인`, 처리 중에도 동일한 접근성 이름 |
| 화면 제목 | `로그인`, `대시보드` |
| 로그아웃 버튼 | `로그아웃` |

필드 오류는 `aria-live="polite"`로 알리고 해당 입력의 설명으로 연결합니다. 인증 실패는 `role="alert"`로, 요청 처리 상태는 `role="status"`로 전달합니다. 키보드 초점에는 `:focus-visible` 표시가 적용됩니다.

비밀번호 입력은 가려진 상태에서 암시적 ARIA 역할이 없으므로 Playwright에서 `getByLabel('비밀번호', { exact: true })`로 찾을 수 있습니다.
